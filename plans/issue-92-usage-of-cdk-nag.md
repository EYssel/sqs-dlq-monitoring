# Implementation Plan - Issue #92: Consider usage of cdk-nag

## Problem Analysis and Context
`cdk-nag` checks CDK constructs for compliance with security and best practice rulesets (e.g. AWS Solutions Rules). Incorporating `cdk-nag` ensures the construct library is secure out-of-the-box.
To implement this:
1. SQS queues must default to `enforceSSL: true` to avoid the `AwsSolutions-SQS3` violation.
2. The SNS Topic doesn't require server-side encryption by default for DLQ alert use-cases (to avoid extra customer costs), so we will suppress the `AwsSolutions-SNS2` violation.
3. The Lambda execution role uses CDK-generated basic execution policies, which trigger wildcard and managed-policy checks. We will suppress these using `NagSuppressions.addResourceSuppressions`.
4. We will add `cdk-nag` assertions to the unit and integration tests.

#### 2. In `src/monitoredQueue.ts`:
```typescript
import { NagSuppressions } from 'cdk-nag';

// Inside deadLetterQueue definition:
      queue: new Queue(
        this,
        'DeadLetterQueue',
        {
          enforceSSL: true, // enforce SSL
          queueName: `${props.queueProps.queueName}-dlq`,
          ...props.dlqProps,
        },
      ),

// Inside main Queue definition:
    const queue = new Queue(this, 'Queue', {
      enforceSSL: true, // enforce SSL
      ...props.queueProps,
      deadLetterQueue,
    });

// After topic creation:
    NagSuppressions.addResourceSuppressions(
      topic,
      [
        {
          id: 'AwsSolutions-SNS2',
          reason: 'SNS topic encryption is not required by default for DLQ alerts. Customers can enable SSE by passing a pre-configured topic or setting masterKey in topicProps.',
        },
      ]
    );

// After slackListener Lambda creation (within deploySharedSlackProvider / addSlackNotificationDestination):
  NagSuppressions.addResourceSuppressions(
    slackListener,
    [
      {
        id: 'AwsSolutions-IAM4',
        reason: 'AWSLambdaBasicExecutionRole is required for standard CloudWatch logging.',
      },
      {
        id: 'AwsSolutions-IAM5',
        reason: 'The wildcard permission is generated by CDK to allow writing logs to the auto-created log group.',
      },
    ],
    true // Apply to child resources (IAM role)
  );
```

#### 3. In `test/monitoredQueue.test.ts`:
```typescript
import { Aspects } from 'aws-cdk-lib';
import { Annotations } from 'aws-cdk-lib/assertions';
import { AwsSolutionsChecks } from 'cdk-nag';

describe('cdk-nag compliance', () => {
  test('MonitoredQueue complies with AwsSolutions rules', () => {
    const stack = new Stack();
    new MonitoredQueue(stack, 'NagTestQueue', {
      queueProps: {
        queueName: 'nag-test-queue',
      },
    });

    Aspects.of(stack).add(new AwsSolutionsChecks({ verbose: true }));

    const errors = Annotations.fromStack(stack).allError();
    expect(errors).toHaveLength(0);
  });
});
```

## Step-by-Step Implementation Guide
1. Edit `.projenrc.ts` to add `cdk-nag` to `peerDeps` and `devDeps`.
2. Run `npx projen` to update dependencies.
3. Import `NagSuppressions` in `src/monitoredQueue.ts`.
4. Apply the `enforceSSL: true` property to all queues constructed inside `MonitoredQueue`.
5. Apply resource suppressions for the SNS Topic and Lambda functions as described.
6. Add the cdk-nag test suite inside `test/monitoredQueue.test.ts`.
7. Run `yarn test` to confirm compliance.
